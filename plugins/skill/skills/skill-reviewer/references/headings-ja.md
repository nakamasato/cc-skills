# 日本語で書かれた skill を見るとき

見出しと文体の基準は言語で変わる。英語の名詞句の感覚をそのまま当てると、日本語としては不自然な見出しになる。**日本語の skill をレビューするときは、この基準で見る。**

## 見出し

| 直すもの | 例 | 案 |
|---|---|---|
| 動詞の言い切り | `スナップショットを取る`・`読む` | 体言止めにする。`スナップショットの取得`・`出力の読み方` |
| 数を数えただけ | `2つの取得元` | `取得元の選択` |
| 何にでも付く名前 | `制約`・`注意`・`補足`・`その他` | 中身を名指しする。`実行環境の制約` |
| 結論が隠れている | `API について` | 結論を出す。`Instructor API の適用範囲` |
| 疑問形 | `どこに置くか` | 節の中身が判断基準なら `配置の判断基準` |

**「〜する」で終わる見出しが並んでいたら、体言止めに統一できないか見る。** 手順書の中の各ステップ（`1. 認証`・`2. 取得`）は名詞のままでよい。

## 文体

- **常体と敬体を混ぜない。** skill は常体（だ・である、または断定を避けた言い切り）で書かれていることが多い。「〜してください」と「〜する」が混在していたら揃える
- **カタカナ語の表記を揃える。** `レビュアー`／`レビューアー`、`サーバ`／`サーバー` のような揺れは、同じものを指していないように読める
- **英数字と日本語の間の空白**を、ファイル全体で揃える。`SKILL.md を読む` と `SKILL.mdを読む` が混ざらないようにする
- **一語一義。** 同じものを「節」「セクション」「章」と呼び分けない

## 指示の強さ

英語の MUST・ALWAYS・NEVER に当たるのは、日本語では**太字の断定**になっていることが多い。段落ごとに太字が入っていたら、その節で本当に落としたくない一文だけに絞る。理由を書けば、読み手は基準から外れた場面でも判断できる。
